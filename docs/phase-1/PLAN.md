## Agreed interfaces and bounded decisions

- Design schema stays 2. Complete project and mutable state schemas become 3. Solver compatibility identity becomes `2.1.0`, model `neptune-reference-2`, algorithm `committed-boundary-1`. Old dynamic semantics are not silently relabeled. Package release version and dependency lockfile remain unchanged until a separately authorized release.
- One `persistence/limits.ts` contract retains the 30-day inclusive project horizon, 10,000 events and 86,400 seconds per synchronous advance. Worker chunks/job budgets are distinct from project validity. UTF-8 admission is 64 MiB; structural/depth limits bound import allocations. These are admission ceilings, not claims that every size/horizon combination is economical; boundary fixtures and measured runs will verify them.
- Each admitted event has a stable contiguous admission sequence. Ordering is `(timeS, sequence)`; existing request events may omit sequence and receive it at admission. This preserves multiple same-time commands across export/replay and avoids host-dependent locale sorting. Events never disappear to satisfy byte limits.
- A committed numerical boundary is after all due recorded events and controller decisions at a completed timestep. Every event is resolved in its declared order; idle chunk boundaries do not rerun controller decisions. `integrationStepS` and `stepIndex` are persisted. Every continuation uses that same timestep sequence.
- Complete state includes physical storage, controller state and startup deadlines, failed assets, ordered authoritative history/applied position, runtime boundary inputs and existing energy counters. Derived solver caches are rebuilt; `solverMs` alone is nondeterministic and normalized to zero. Presentation log retention remains the existing 1,000-entry bound.
- Project API: `projectFile(design,state,options?)`, `parseProject(text)`, `serializeProject(project)`, `compatibilityFor(project)`, `restoreProject(project) -> {design,state}`, `recalculateProject(project) -> CurrentProject` (scenario only, labeled parent), `normalizeProject(project)`. Legacy schema-2 projects remain scenario-only with original version identity; incompatible schema-3 models remain inspectable/re-exportable, and exact continuation is disabled. Recalculation is explicit and separate.
- Shared failures are serializable `FailureDiagnostic`s: invalid input, unsupported configuration, numerical failure, resource limit and storage failure. Adequacy remains existing solved constraint status; the shared network is not enlarged and open Gen III ties gain no supply credit.
- Worker response status distinguishes progress/completion/cancellation/resource exhaustion/failure. Every published state is a validated checkpoint. UI uses both epoch and request ID, stores only committed state, and retains manual export after storage failure. Pending replay target can be recorded separately in project execution metadata.
