## Promotion requirements

1. Install the existing lockfile, then pass typecheck, lint, all unit/integration tests with both real telemetry integrations, production build, and prototype/Phase2/Phase3/Phase4 browser journeys in Chromium, Firefox and WebKit. Retries remain zero. Only the two historical Chromium/WebKit500,000 prototype Step10s exclusions apply; previously deferred Phase1 stress work stays deferred.
2. Obtain independent engineering review, then passing source CI on the final candidate. Re-fetch main and compare the CI-tested merge tree, reviewed candidate and actual accepted tree. Preserve legitimate concurrent changes and repeat affected gates if they differ.
3. Immediately before promotion, re-fetch `codex/pages` and verify the actual last-known-good artifact. Expected Phase3 rollback is `84366132ae9499bdd3f47fd8d2b53864df2cc0a5`, not its Phase2 parent. Preserve it as a Git bundle/archive outside temporary worktrees and verify the public release still matches it.
4. Rebuild accepted main and package using existing `package-preview.mjs --channel=production` evidence arguments. Compiled/static manifest and bytes must match the frozen tested build. Only `release.json` may differ in source/branch/build-time/promotion evidence; `build-manifest.json` must remain identical when payload bytes match. Preserve the entire `v2-preview` tree `531d00a67da4c1f2f02a22bf249d93e683b2601b`, including its tracked marker files.
5. Publish through a normal commit/push to the established `codex/pages` branch, observe its actual deployment, and run the existing full public verifier against the staged committed artifact. Derive all file counts from Git/manifests; verify public HTTP bytes and non-HTTP dotfile markers through Git. Run the complete hosted browser gate with release identity checked before and after. Record console/asset failures and require a stable artifact throughout.

## Critical hosted failure

A successful upload does not establish acceptance. If a critical hosted gate fails, re-fetch Pages and inspect intervening releases before restoring the captured last-known-good artifact with a **new normal commit**. Preserve the preview and normal source history. Do not force-push, roll back an unrelated newer release, or permit an automatic trigger to immediately overwrite the restoration. Observe and byte-verify the rollback deployment, then report which source and artifact are actually live. A blocked operation must be reported with its exact remaining gate; do not call local, merged or uploaded work live-verified.

No hosting migration, backend, dependency change, new physical/network solver, training-throughput estimate, optimizer or physical commissioning is part of this release. Keep **Simulated, design-stage prototype** visible.
