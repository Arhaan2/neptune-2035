# Phase 3 demonstration

All screens describe a simulated, design-stage prototype. A network capacity pass is a check of declared offered traffic against modeled resources, not a claim about AI training performance or complete physical campus feasibility.

1. Wait until **Step 10s** is enabled. In **Starting scenario**, choose **100,000 campus**. A legacy starting design receives the **Scalable reference network**; an existing Phase 3 design retains its selected network mode. Existing scale presets select fixed core tiers by platform count.
2. In the normal right-hand inspector (below the scene on mobile), find **Network capacity**. Choose **Scalable reference network** in **Network configuration** and use **Apply network and reset** if that mode is not already installed.
3. Open **Saved workload assumptions**. Inspect the saved profile version, required classes, units, direction and conservative platform-domain job policy. Enable required external networking in the existing **Design assumptions** controls to include the declared external demand.
4. Read **Installed design demand** separately from **Current energized demand**. The full campus has 12,500 whole nodes and offers 1,250 Gbit/s cluster demand; when external networking is required it adds 12.5 Gbit/s. Current supply or failures can reduce energization without changing provisioning requirements.
5. Select **Inspect shared core**. **Selected resource budgets** lists actual resource identities, demand, rating, headroom and affected-domain counts. **Ratings and ports** and the inventory/report exports inspect the same installed specifications. **Inspect network asset** selects platform switches directly.
6. Choose **Undersized shared-core network**, then **Apply network and reset**. The previous complete checkpoint and events are preserved in **Compare**. The new run starts paused at 0 s. The 400 Gbit/s shared switch resource now blocks the campus's required jobs. Select its reported limiting resource to inspect it.
7. Return to **Scalable reference network** with **Apply network and reset**. Select **platform-001/cluster** under **Inspect network asset**, click **Trip selected asset**, and observe current affected domains. Click **Restore selected asset** to restore modeled connectivity. Selecting **shore/cluster-core** and tripping it demonstrates the shared common-mode dependency.
8. With the platform switch selected, open **Network links · enable / disable**. Choose **Disable network link and reset** for its upstream cluster link; inspect the disconnected local domain. **Enable network link and reset** restores that path. These controls are explicitly design revisions and preserve the previous run; they do not invent runtime rerouting.
9. Use **Step 10s** to advance the actual simulation clock. Select **project** in **Export artifact** to download the full project JSON. **Import project** restores its supported design and exact checkpoint. Reload the page and select **Recover saved checkpoint** after initialization. **Compare** also contains the saved pre-change experiments.

Legacy `#s=` URLs carry Legacy v0.1 configuration only. Share Phase 3 through Project JSON to retain topology, equipment, assumptions, event mappings and checkpoints. Older Phase 2 project files remain inspectable/exportable; use their explicit recalculation action to derive a separate current-model experiment while retaining their original topology.

Supply allocation includes declared network electrical demand. Shore equipment mass remains outside floating-platform accounting. Module network heat uses the existing module thermal model; shore/platform network cooling remains outside that model. Included cost is an assumption subtotal with explicit exclusions.
